# Week 1 Seminar: Build a Connected Profile Website

## Goal

Complete and debug a small multi-page website. By the end, every page should contain valid HTML, meaningful content, and reliable navigation.

## Core requirements

1. Inspect the supplied folder before editing. Identify the current document and target resource whenever you write a path.
2. Repair the document structure and metadata in every HTML file. Each page needs a suitable `lang`, character encoding, viewport setting, and unique `title`.
3. Complete `index.html` with a main heading, introductory paragraph, profile image, interests list, and meaningful links.
4. Complete the Profile, About Us, and Education pages with appropriate headings, paragraphs, and at least one list across the site.
5. Make the profile image display from the `images` folder. Give it useful alternative text.
6. Add a consistent link group so users can reach Home, Profile, About Us, and Education from every page.
7. Find and repair the deliberate structural and path errors in the starter files.
8. Test every link and image from every page. Do not rely only on the browser Back button.
9. Be ready to explain two paths: one same-folder path and one child-folder path.

## Checkpoints

- **Checkpoint 1:** All four pages have valid skeletons and distinct titles.
- **Checkpoint 2:** `index.html` contains meaningful structured content.
- **Checkpoint 3:** The image loads and its `src` can be explained segment by segment.
- **Checkpoint 4:** Every page is reachable and offers a way onward or back.
- **Checkpoint 5:** A peer can navigate the site without encountering a broken resource.

## If you finish early

Complete `pages/contact.html`, link to it from the Profile page, and add a correct route back to Home.

## Submission evidence

Submit the completed website folder and a short note containing:

- one problem you found;
- how you diagnosed it;
- the path you corrected; and
- why the corrected path works.

AI assistance may be used if permitted by the instructor, but you must be able to explain, evaluate, and debug the resulting code.
